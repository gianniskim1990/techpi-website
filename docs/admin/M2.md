# TechPi admin: Task M2, the 7 Insights articles connected

Status: **implemented and tested locally against a mocked GitHub** (branch `feat/techpi-admin-m2-insights`, based on

## 1. What M2 does

The 7 existing Insights articles are managed through the custom admin, like the 18 case studies ([M1B.md](M1B.md)).
For each article the admin loads the real content from GitHub, edits its text, lists, note, related reading and search
title and description, validates, detects conflicts, and saves a draft to the article's own branch
`cms/insights/<slug>` with one draft pull request into `feat/techpi-admin-m2-insights`. Saving never changes techpi.eu.
The articles are **English only**: no Greek version exists or can be added, and no `/el/insights` route or hreflang is
created. "New article" and Publish are disabled.

## 2. Content migration

The 7 articles were extracted **programmatically** (no value retyped) from `src/content/insights.ts` into
`content/insights/<slug>/index.json`. `insights.ts` keeps the types, the index and template copy and the related-slug
check; it lists the 7 files explicitly, validates each on every build (`admin/shared/insight-content.js`) and orders them
by the locked `facts.order` (newest first; the build fails unless the positions are exactly 1 to 7). The page templates
(`InsightPage.astro`, `InsightsIndexPage.astro`, `pages/insights/[slug].astro`) are unchanged.

## 3. Editable and locked

| Editable (English) | Locked |
|---|---|
| Category, title, lead | Slug and URL `/insights/<slug>` |
| Every section heading | Position on the Insights index (newest first) |
| Paragraphs, list items and paragraphs after the list, inside existing parts (add, remove, reorder items) | The original publication date (`datePublished`) and how the page writes it |
| The note's text, where the article has one, with `[label](/page)` links to known pages of this site | The legacy source URL (redirect map; never rendered) |
| Related reading: up to 4 of the other 6 articles, in order | The structure: number of sections, which parts each has, whether there is a note |
| Search title (at most 70 characters) and meta description (70 to 200), as the site's SEO validator requires | Language: English only. No author, modified date, reading time or image exists or can be added |

Link rules: links are allowed only in the note (the template renders them nowhere else) and only as
`[label](/path)` to one of the site's English pages (the static pages, the 18 case studies and the 7 articles). External
URLs, protocol-relative URLs, `javascript:`, `mailto:`, `data:`, query strings, fragments, relative paths, Greek pages,
unknown articles and malformed or nested links are refused. Markup (`<` `>`), line breaks and draft markers
(placeholder, TODO, lorem ipsum, ...) are refused everywhere.

## 6. Known limitations

- **Headings and the Insights validator.** `scripts/content/validate-insights.mjs` deliberately checks each article's
  section headings against the original source. A draft that changes a heading saves normally, but that draft's preview
  build fails the validator until the expected headings are updated in a separate, approved change. The editor warns
  when a heading differs from the saved version.
- The search preview approximates how search engines shorten titles and descriptions.
- Not built: new articles, Greek versions, images, publishing, preview of the draft site, and adding or removing sections,
  parts or the note. Website pages remain the read-only snapshot.
